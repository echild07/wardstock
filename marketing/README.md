# Marketing materials

- **The live flyer now ships as part of the app** — `godaddy/app/marketing.html` (moved here, no longer a separate standalone artifact — reachable as a real page on the live site, linked from `login.php`'s footer alongside Privacy/Terms). LeeWard-branded, covers WardStock's features, the two-piece architecture ("At Sea" / "At Harbor" — WardStock vs. the Lucius engine, with the privacy angle: raw data and analytics stay on your own home server, never a shared cloud), and a LeeWard copyright/IP-ownership footer. Fully self-contained (fonts via Google Fonts CDN link, the logo embedded directly as a base64 `data:` URI — no relative file dependencies, safe to have moved without breaking anything).

- **This folder now holds source assets and docs only, not the shippable file:** `leeward_logo_transparent.png` (source logo, already embedded in the HTML — kept here for any future redesign/re-embed) and this README.

- **PDF generation: works, but build on demand, not by default** — `wkhtmltopdf` can render this to PDF (page-size Letter, local font substitutes needed since this environment can't reach Google Fonts at render time — see the `<link>` swap needed for `Liberation Serif/Sans/Mono` in place of `Fraunces/Inter/Space Mono`). **One known rendering bug to remember:** the two-column "At Sea / At Harbor" comparison uses an HTML `<table>` (CSS Grid/Flexbox/floats all failed identically in `wkhtmltopdf`'s old rendering engine — confirmed via isolated testing, not assumed) — and specifically, **`border-radius` on a `<td>` causes this engine to silently collapse the whole table to stacked rows instead of side-by-side columns.** The current file has no `border-radius` on `.harbor-card` for exactly this reason — if that ever gets re-added (e.g. during a redesign), the columns will silently break again in PDF output only (the live HTML in a real browser is unaffected).

Only regenerate the PDF when actually needed — it took real iteration to get right, and the source HTML (now `godaddy/app/marketing.html`) is the thing worth keeping current, not a pre-built PDF.

**Alternative that worked better, when `wkhtmltopdf` isn't installed:** headless Edge or Chrome's built-in `--print-to-pdf` (e.g. `msedge --headless --disable-gpu --no-pdf-header-footer --print-to-pdf="out.pdf" --virtual-time-budget=8000 --run-all-compositor-stages-before-draw "file:///path/to/godaddy/app/marketing.html"`). Confirmed via real output, not assumed: this renders the real Google Fonts (Fraunces/Inter/Space Mono) directly rather than needing the local-font substitution `wkhtmltopdf` required, and — since it's a modern Chromium engine, not `wkhtmltopdf`'s old one — the `border-radius`-collapses-the-table bug documented above doesn't apply here regardless of whether `.harbor-card` ever gets a `border-radius` added back. `--virtual-time-budget` matters: without giving the page a moment to actually finish loading the remote web fonts before the PDF renders, they can silently fail to appear.
