- **Real bug found and fixed after the move: GoDaddy 500'd on this page.** The file was ~2MB as originally moved — the logo was embedded twice, directly as base64 `data:` URIs (a company-mark version and a larger emblem version), which is what made it self-contained but also made it huge. GoDaddy's shared-hosting stack (cPanel's own generic error page, not a PHP error — confirmed by checking the actual response body, not assumed) rejected serving a static response that large. **Fixed by extracting both images back out to real files** — `godaddy/app/marketing-mark.png` and `godaddy/app/marketing-emblem.png` — referenced via normal `<img src="...">` instead of inline base64. `marketing.html` itself dropped from ~2MB to ~17KB. **This means the page is no longer fully self-contained** — those two PNGs must ship alongside it in `godaddy/app/` (they're regular tracked files there now, not a "don't need to upload this" case like `config/`).

- **This folder now holds source assets and docs only, not the shippable files:** `leeward_logo_transparent.png` (original source logo the two extracted PNGs were cropped/exported from — kept here for any future redesign) and this README.

- **PDF generation: works, but build on demand, not by default** — `wkhtmltopdf` can render this to PDF (page-size Letter, local font substitutes needed since this environment can't reach Google Fonts at render time — see the `<link>` swap needed for `Liberation Serif/Sans/Mono` in place of `Fraunces/Inter/Space Mono`). **One known rendering bug to remember:** the two-column "At Sea / At Harbor" comparison uses an HTML `<table>` (CSS Grid/Flexbox/floats all failed identically in `wkhtmltopdf`'s old rendering engine — confirmed via isolated testing, not assumed) — and specifically, **`border-radius` on a `<td>` causes this engine to silently collapse the whole table to stacked rows instead of side-by-side columns.** The current file has no `border-radius` on `.harbor-card` for exactly this reason — if that ever gets re-added (e.g. during a redesign), the columns will silently break again in PDF output only (the live HTML in a real browser is unaffected).

**New page added (Ward, Aug 2026): "The Chart Room" — a reference page explaining all 20 of wherewhen's analyses** (reference number, display name, inputs, what it computes — kept literally sourced from `homeassistant/nodered/analysis_engine_flow.json`'s own registry, not reconstructed from memory, since it's going into a printed document). Starts on its own page via `page-break-before: always` on `.reference-section`. **Its row layout (`.ref-row`) uses CSS Grid** — same technique the original "At Sea / At Harbor" comparison used before it was switched to an HTML `<table>` specifically because `wkhtmltopdf`'s old engine can't render Grid/Flexbox/floats as side-by-side columns (see above). This new section doesn't need side-by-side columns (it's one column, numbers/names/details stacked), so Grid collapsing to a plain block layout in `wkhtmltopdf` would still read fine, just not as tidy — but if it ever needs real multi-column alignment, use a `<table>` instead, not Grid, for the same reason. The headless Chrome/Edge path (below) renders it correctly either way.

**Second reference page added (Ward, Aug 2026): "The Engine Room" — lists every non-test Node-RED flow** (name, purpose, how often triggered), same sourced-from-the-actual-flow-files discipline as the Chart Room, not reconstructed from memory — pulled directly from each flow's tab `info` field and its inject node(s)' `crontab`/`repeat` config. Same `.reference-section`/`page-break-before` pattern, its own page. Test/diagnostic flows (`*_test.json`, `sqlite_test_flow.json`, `system_test_flow.json`) are deliberately excluded — this page is "what runs the ship," not "what verifies it still runs." **Keeping this current going forward:** any time a live flow is added, removed, renamed, or its schedule changes, this page needs the same update — it'll drift exactly like the Chart Room would if analyses changed without the page being touched.

Only regenerate the PDF when actually needed — it took real iteration to get right, and the source HTML (now `godaddy/app/marketing.html`) is the thing worth keeping current, not a pre-built PDF.

**Alternative that worked better, when `wkhtmltopdf` isn't installed:** headless Edge or Chrome's built-in `--print-to-pdf` (e.g. `msedge --headless --disable-gpu --no-pdf-header-footer --print-to-pdf="out.pdf" --virtual-time-budget=8000 --run-all-compositor-stages-before-draw "file:///path/to/godaddy/app/marketing.html"`). Confirmed via real output, not assumed: this renders the real Google Fonts (Fraunces/Inter/Space Mono) directly rather than needing the local-font substitution `wkhtmltopdf` required, and — since it's a modern Chromium engine, not `wkhtmltopdf`'s old one — the `border-radius`-collapses-the-table bug documented above doesn't apply here regardless of whether `.harbor-card` ever gets a `border-radius` added back. `--virtual-time-budget` matters: without giving the page a moment to actually finish loading the remote web fonts before the PDF renders, they can silently fail to appear.
